# s17 - Goal Loop 我的理解

## 1. 一句话核心

**"模型不再调用工具，只代表这一轮想停；目标是否完成，再交给一个独立判断器"**——在 s16 agent_loop 的"无 tool_calls"分支前加一个 **Goal Stop hook**：用另一个独立模型调用判断"完成条件是否满足"，不满足就**自动续轮**，满足才 return。

教材：*"The model proposes a stop; an independent evaluator decides whether to continue."*；Harness Layer 定位 **continued execution — check a completion condition at the end of every turn, start another turn when work remains**。

本项目实现见 [s17_goal_loop.py:29-38](s17_goal_loop.py#L29-L38)（GoalState）、[s17_goal_loop.py:41-88](s17_goal_loop.py#L41-L88)（PromptGoalEvaluator）、[s17_goal_loop.py:97-139](s17_goal_loop.py#L97-L139)（GoalDecision + GoalController）、[s17_goal_loop.py:142-147](s17_goal_loop.py#L142-L147)（has_pending_async）、[s17_goal_loop.py:151-181](s17_goal_loop.py#L151-L181)（parse_goal_command）、[s17_goal_loop.py:183-274](s17_goal_loop.py#L183-L274)（agent_loop 接入 Goal Stop hook）。

## 2. 4 个核心组件

### ① GoalState（[L29-38](s17_goal_loop.py#L29-L38)）

```python
@dataclass
class GoalState:
    condition: str                              # /goal 后面的条件
    status: str = "pending"                     # pending | completed | impossible
    eval_count: int = 0                         # 累计 block 次数
    start_time: float = field(default_factory=time.time)
    latest_reason: str = ""                     # 最近一次 evaluator 给的 reason
    def elapsed(self) -> float: ...             # 自 start_time 起的秒数
```

**内存存，不持久化**——重启进程 Goal 状态丢（教材 CLI 一致）。

### ② PromptGoalEvaluator（[L41-88](s17_goal_loop.py#L41-L88)）

```python
EVAL_SCHEMA = s16.SimpleJsonSchema(
    required=["ok", "reason"],
    types={"ok": bool, "reason": str, "impossible": bool},
)
```

**独立 LLM 调用**——不复用主 agent，**复用 s16.RealAgentRunner + SimpleJsonSchema**（schema 校验 + 1 次重试免费拿）。

**prompt 关键约束**（教材 L83-88）：
- "Base your answer ONLY on concrete actions or results shown in the conversation"
- "Reject claims with no supporting evidence"

**`evaluate()` 异常处理**：try/except 包裹 → 失败返 `{"ok": False, "reason": "Evaluator error: ...", "impossible": False}` → **不崩 loop**。

**`_truncate_messages`**（[L51-65](s17_goal_loop.py#L51-L65)）：
- 保留最近 `KEEP_RECENT=20` 条消息
- 单条消息 > 4000 字符 → 留首 2000 + `\n...[truncated]...\n` + 末 2000

**为什么 evaluator 没工具**（教材设计原则）：
1. 保持**独立性**——不被工具结果二次污染
2. 强制 **worker 自证**——主模型必须自己跑验证 + 把结果写进对话
3. 判断**快速轻量**——只用 LLM 读文本

### ③ GoalController（[L97-139](s17_goal_loop.py#L97-L139)）

```python
class GoalController:
    MAX_CONSECUTIVE_BLOCKS = 3   # 外部出口

    def set/inspect/clear/evaluate_after_turn(...)
```

**`evaluate_after_turn(messages, has_pending_async)` 决策表**：

| 状态 | action | 副作用 |
|------|--------|--------|
| `state is None` | `pass` | 无（无 Goal 行为和 s16 一样） |
| `has_pending_async` | `defer` | 保留 Goal，跳过 evaluator |
| evaluator.ok=True | `pass` | state.status=completed |
| evaluator.impossible=True | `block` | state.status=impossible |
| 普通 block | `block` | state.eval_count += 1，state.latest_reason 更新 |
| `eval_count > MAX_CONSECUTIVE_BLOCKS + 1`（即 5）| `pass` | 强制出口，reason 写"Goal exceeded 3 blocks" |

**block 计数边界**（过程修复 #2）：`> MAX + 1` 而不是 `>= MAX`——确保**第 4 次 block 后才强制 pass**（教材 "3 次 block 后"语义）。

### ④ has_pending_async（[L142-147](s17_goal_loop.py#L142-L147)）

```python
def has_pending_async() -> bool:
    bg_tasks = getattr(s14.BACKGROUND, "tasks", {})
    if any(t.get("status") == "running" for t in bg_tasks.values()):
        return True
    return any(t.status == s16.TaskStatus.RUNNING for t in s16.scheduler_tasks.values())
```

**双查**：
- s14.BACKGROUND.tasks（s11 后台 bash）
- s16.scheduler_tasks（s16 workflow）

**为什么用 `getattr(s14.BACKGROUND, "tasks", {})`**：s14.BACKGROUND 接口可能字段名不同，**fail-safe**（背景任务查询失败 → 视为无 background，不阻断 Goal 评估）。

## 3. /goal CLI 命令（[L151-181](s17_goal_loop.py#L151-L181)）

`parse_goal_command(q)` 返 `("kind", "arg") | None`：

| 输入 | 输出 |
|------|------|
| `/goal` / `/goal status` / `/goal show` / `/goal view` | `("inspect", "")` |
| `/goal clear` / `stop` / `off` / `reset` / `none` / `cancel` | `("clear", "")` |
| `/goal <condition>` | `("set", condition)` |
| 非 `/goal` 开头 | `None`（走普通 agent_loop） |

**大小写处理**：用 `q.lower().startswith("/goal")` 接受大写变体，但**保留 condition 大小写**（避免 condition 含大写被错改）。

## 4. /goal set 立即触发工作（[L316-324](s17_goal_loop.py#L316-L324)）

教材 L25-29 明确："immediately gives it to the main model as the current task"：

```python
elif kind == "set":
    goal_controller.set(arg)
    history[0]["content"] = _build_system_prompt([], True)  # 重建 system prompt（含 goal 段）
    history.append({"role": "user", "content": arg})        # 立即当任务执行

        s14.trigger_hooks("UserPromptSubmit", arg)           # 触发 UserPromptSubmit hook

    print(flush=True)
```

**关键不变量**：set 后**不等用户再发消息**，**自动开始干活**。

## 5. agent_loop 接入 Goal Stop hook（[L183-274](s17_goal_loop.py#L183-L274)）

```python
def agent_loop(messages, active_request, goal_controller):
    reactive_retries = 0
    while True:
        # 钩子 1-5：借 s15 4 薄包装 + drain + compaction
        # ... s16 同样的 6 钩子流程 + reactive 限流 + Workflow dispatch ...
        
        if not msg.tool_calls:
            # Goal Stop hook（s17 新增，在 s15._hook_stop 之前）
            decision = goal_controller.evaluate_after_turn(messages, has_pending_async())
            if decision.action == "block":
                messages.append({"role": "user", "content": f"[Goal block #{state.eval_count}] {decision.reason}"})
                continue  # 续轮
            # pass / defer / error → 走 s15._hook_stop（summary_hook 统计 + 记忆提取）
            force = s15._hook_stop(messages)
            if force: ...; continue
            if msg.content: print
            s14.extract_memories(messages)
            return
        # ... tool dispatch ...
```

**6 钩子 → 7 钩子**：
- 钩子 1-5：借 s15 4 薄包装 + drain + compaction + LLM + 工具 dispatch
- **钩子 6（新）：Goal Stop hook**（仅在 `not msg.tool_calls` 时跑）
- 钩子 7：s15._hook_stop（summary_hook + 记忆提取）—— 排在 Goal 之后

**Goal block 优先于 summary_hook**：Goal block → 续轮，不打印、不提取记忆。Goal pass → 走 _hook_stop 正常退出。

## 6. /goal 条件"可检查"三要素

教材强调"checkable"原则：

| 要素 | 含义 |
|------|------|
| **结束状态** | 最终要达到什么 |
| **验证方式** | 用哪个命令/输出证明 |
| **限制条件** | 过程中不能破坏什么 |

反例："把代码弄好"——evaluator 不知道"好"是什么。
正例："完成登录模块迁移，直到 pytest tests/auth 退出码为 0，**并且没修改 tests/auth 之外的测试文件**"。

## 7. 3 个退出路径

| 路径 | 触发 | 行为 |
|------|------|------|
| **Goal pass** | evaluator.ok=True | 走 _hook_stop 退出（正常流程） |
| **Goal impossible** | evaluator.impossible=True | 仍 block 续轮，但 state.status=impossible，下次"用户输入"会清掉？ |
| **强制出口** | eval_count > MAX+1 | 走 _hook_stop 退出，reason="Goal exceeded 3 blocks; ..." |

**教材 L139-146 两个外部出口**：
1. **全局 max_turns**（主循环限制）
2. **Stop hook 连续阻止上限**（`MAX_CONSECUTIVE_BLOCKS`）

达到上限 → 把控制权还给用户 → **不假装完成**、**不自动清 Goal**。

## 8. 与 s16 的关系

| 章节 | 解决什么问题 |
|------|-------------|
| s16 | **一批工作怎样执行**：哪些并行、怎么验证、断了怎么续 |
| s17 | **整件事情是否完成**：Workflow 完成 ≠ 用户目标完成 |

**两者独立可用，也可一起用**——s16 的 Workflow 完成通知进对话后，s17 的 Goal evaluator 判断是否继续。

## 11. 过程修正记录（3 个 fix）

**事故 A（_SLUG 否定字符类）**：和 s16 同样的错位（继承 bug）——
- 错误：`r"[^a-zA-Z0-9_-]"` 否定字符类，`fullmatch` 对合法字符串返 False，对含非法字符返 True
- 修复：`r"^[a-zA-Z0-9_-]+$"` 肯定字符类
- **教训**：跨章节复用 utility 函数时，**必须重读**而不是 copy-paste

**事故 B（eval_count 阈值边界）**：
- 错误：原写 `if self.state.eval_count >= self.MAX_CONSECUTIVE_BLOCKS`（>= 3 强制 pass）
- 实际：第 3 次 block 就 pass = 只 block 2 次
- 修复：`> self.MAX_CONSECUTIVE_BLOCKS + 1`（> 4 强制 pass）= **block 4 次后第 5 次 pass**
- 测试断言同步更新（d5 后检查 eval_count==3 → 改逐次断言）

**事故 C（_SLUG 修复未审）**：s17 的 60 验收用例里 _SLUG 测试沿用 s16 测试风格，但修复没立即加测试 → 加 2 个用例确认 ✓

## 12. 一句话回顾

s17 = **"独立判断器 + 自动续轮 + 可检查条件"**。价值在"模型说做完 ≠ 真的做完"——加一道独立 LLM 评估，让用户**不写"继续"也能自动续**，到上限才交还控制权。**这是 s01-s17 体系的最后一环**——s01 开环，s17 闭环。
