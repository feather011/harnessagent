# s06 - Subagent

## 1. 一句话核心

给父 agent 加一个 `task` 工具：调用时**用全新 `messages[]` 同步跑一个子 agent 循环**，子循环结束只把它的最终文本作为工具结果回给父——中间的对话不进入父上下文。

教材原话：*"A subagent starts with a fresh `messages[]`. Its final text returns to the parent; its intermediate conversation does not."*；Harness Layer 定位为 **Delegation — Run a focused task in a separate conversation context**（README 第 7-9 行）。动机：父 agent 修 bug 时读很多文件追踪调用链，这些中间细节理解完就没用了，却一直占着父的上下文（README 第 15 行）。

本项目实现见 [s06_subagent.py:335-384](s06_subagent.py#L335-L384)（run_subagent）、[s06_subagent.py:388-402](s06_subagent.py#L388-L402)（TASK_TOOL + 注册）。

## 2. 5 个边界决策

教材 README 第 77-83 行给出子 agent 的 5 个设计边界，映射到项目代码：

| 决策 | 选择 | 理由 | 项目代码 |
|---|---|---|---|
| Conversation | **全新 `messages[]`** | 父历史不复制给子 | 子从 `[system(SUB_SYSTEM), user(prompt)]` 起（[L338-341](s06_subagent.py#L338-L341)） |
| Execution | **同进程、同 WORKDIR** | 文件系统变化双方可见（子写的文件父能读） | 子 handler 与父共用同一批函数（[SUB_HANDLERS L331-332](s06_subagent.py#L331-L332)） |
| Return value | **只回 final text** | 子中间工具调用不进入父 messages | `return msg.content or "(no summary)"`（[L355](s06_subagent.py#L355)） |
| Delegation depth | **SUB_TOOLS 不含 task** | 只允许一级 delegation | `SUB_TOOLS = list(BASE_TOOLS)`（[L331](s06_subagent.py#L331)） |
| Tool policy | **共享 HOOKS** | 父子同一套 permission 检查 | 子也走 `trigger_hooks("PreToolUse", ...)`（[L366](s06_subagent.py#L366)） |

**关键性质**（README 第 25 行）：*"This is message isolation, not process or filesystem isolation."*——隔离的是对话消息，不是进程/文件系统。父子共享 `WORKDIR` 和全局 `_DENY_ALL`。

## 3. SUB_TOOLS 不含 task 的设计意图

```python
SUB_TOOLS = list(BASE_TOOLS)   # 子只有 6 个基础工具（bash/read/write/edit/glob/todo_write）
```

- **防二级 delegation**：子 agent 手里没有 `task` 工具，模型不可能让"子再派子"，delegation 深度锁死在 1 层（README 第 82 行 "This lesson permits one delegation level"）
- **`list(BASE_TOOLS)` 而非 `list(TOOLS)`**：`TOOLS` 是父的 7 个（含 task），若复制它会连 task 一起给子——这是最容易写错的地方
- **浅拷贝**：`list()` / `dict()` 复制的是引用，工具的 schema 和 handler 函数与父共享，不重复定义

## 4. OpenAI 协议 vs Anthropic 协议差异

教材 s06 `code.py`（Anthropic）对项目 `s06_subagent.py`（OpenAI/DeepSeek）：

| 维度 | 本项目（OpenAI） | 教材（Anthropic） |
|---|---|---|
| **SUB_SYSTEM 传递** | **必须进子 messages[0]**：`[{"role":"system","content":SUB_SYSTEM}, {"role":"user","content":prompt}]`（[L338-341](s06_subagent.py#L338-L341)） | `create(system=SUB_SYSTEM, ...)` 独立参数，不在 messages 里 |
| final text 提取 | `msg.content` 直接是 **str**（[L355](s06_subagent.py#L355)） | `response.content` 是 **block 列表**，要 `extract_text()` 拼 text block |
| 工具 schema | `parameters` + `minLength: 1`（[L394-397](s06_subagent.py#L394-L397)） | `input_schema` |
| dispatch 复用 | 父子各自内联 `for call in msg.tool_calls` 循环 | 抽了 `execute_tool(block, handlers)` 父子共用 |

**关键差异（SUB_SYSTEM）**：OpenAI 协议没有 `system=` 参数，system 消息只能放 `messages[0]`。如果照抄教材的 `messages = [{"role":"user","content":prompt}]`（只放 user），**子 agent 将没有 SYSTEM 引导**——必须在子 messages 开头显式加 SUB_SYSTEM。

## 5. 本项目对参考代码的 N 项适配

1. **BASE_TOOLS / BASE_HANDLERS 抽出**（[L115-169](s06_subagent.py#L115-L169)、[L317-324](s06_subagent.py#L317-L324)）：基础 6 工具（含 todo_write，教材的 BASE 只有 5 个无 todo）提为 BASE，父 = `[*BASE_TOOLS, TASK_TOOL]`（7），子 = `list(BASE_TOOLS)`（6）
2. **SUB_SYSTEM 进子 messages[0]**（[L338-341](s06_subagent.py#L338-L341)）：OpenAI 协议适配——没有 `system=` 参数，system 只能放 messages
3. **子消息全程 `_strip_surrogates`**（[L344](s06_subagent.py#L344)、[L347](s06_subagent.py#L347)）：与父一致，防 DeepSeek 偶发 surrogate 崩 SDK
4. **blocked 分支加控制台打印**（[L368](s06_subagent.py#L368)）：子被 permission 拦时打印 `[sub] bash(DENIED): ...`，教材的 `execute_tool` 只返回 blocked 字符串不打印
5. **final text 直接 return**（[L355](s06_subagent.py#L355)）：OpenAI 的 `msg.content` 是 str，不需要教材的 `extract_text()`
6. **TASK_TOOL 用 OpenAI function schema**（[L388-399](s06_subagent.py#L388-L399)）：`type/function/parameters` 包裹 + `minLength: 1`
7. **保留 todo_write + rounds_since_todo 提醒**（[L524-527](s06_subagent.py#L524-L527)）：s05 功能在父循环里原样保留
8. **run_subagent 内部也有 Stop hook**（[L350](s06_subagent.py#L350)）：子退出前同样过 `trigger_hooks("Stop")`，与父一致

## 6. N 个最佳实践亮点

1. **30 轮上限 + 强制退出消息**（[L342](s06_subagent.py#L342)、[L384](s06_subagent.py#L384)）：子死循环也有 token 上限，返回 "Subagent stopped after 30 turns without a final answer."
2. **子 context 独立**（[L338-341](s06_subagent.py#L338-L341)）：父 messages 不被子的中间过程撑爆（README 的隔离点）
3. **共享 HOOKS → permission 对子同样生效**（[L366](s06_subagent.py#L366)）：子调 sudo 也被拦，权限不因嵌套而绕过
4. **浅拷贝不共享可变对象**（[L331-332](s06_subagent.py#L331-L332)）：`list()`/`dict()` 各自一份，父改 TOOLS 不影响子
5. **`[sub]` 灰色日志 + `[Subagent started/done]` 紫色标记**（[L337](s06_subagent.py#L337)、[L354](s06_subagent.py#L354)、[L379](s06_subagent.py#L379)）：父子执行路径在控制台一眼可分
6. **只回 final text**（[L355](s06_subagent.py#L355)）：父拿结论不拿过程，上下文最小化
7. **`or "(no summary)"` 兜底**（[L355](s06_subagent.py#L355)）：子返回空 content 时给父一个占位而非 None
8. **坏 JSON / 未知工具在子循环里同样兜底**（[L358-365](s06_subagent.py#L358-L365)、[L375](s06_subagent.py#L375)）：子循环不因单个工具失败而崩

## 7. ⚠️ 主观理解待补充 [❓ 用户补充]

代码能客观看出的摩擦点（作为线索）：

- 子 agent 的 `[sub]` 打印截断到 100 字符，父的 `> <工具>(...)` 截断到 200——输出很长时子侧信息更少（可观测性权衡）
- 父子共享 `_DENY_ALL` 全局：父一旦 deny all，子也全拒（讲义坑 5 提过，s12 worktree 隔离才处理）
