# s12 - Cron Scheduler

## 1. 一句话核心

**线程每秒检查时间，到点等 agent 空闲，空闲了塞 `[Scheduled]` 消息**——把"run tests every morning at 9am"变成可存储的调度，而不需要用户到点再提交一次 prompt。s11 解决了"命令启动后怎么跑"，s12 解决"工作何时开始"（README 第 9-13 行）。

本项目实现见 [s12_cron_scheduler.py:1434-1761](s12_cron_scheduler.py#L1434-L1761)（CronJob + CronScheduler 类）、[s12_cron_scheduler.py:2142-2210](s12_cron_scheduler.py#L2142-L2210)（agent_loop 集成）。

## 2. s12 vs s11 对比（后台任务 vs 定时任务）

| | s11 Background | s12 Cron |
|---|---|---|
| 触发源 | 命令**完成** | 本地时间**到点** |
| 投递内容 | `<task_notification>`（命令结果） | `[Scheduled] {prompt}`（新任务） |
| 谁来跑 | 同 turn 的后续轮次收集 | queue processor 线程在 agent 空闲时启动 turn |
| 存储 | 无（进程内） | `.scheduled_tasks.json`（durable） |
| 时间概念 | 无 | 5 字段 cron 表达式 |

教材强调 s12 **不含 s11 后台命令**（README 第 30 行：因为本章投递的是"开始工作的 prompt"，不是"已运行命令的结果"）；本项目是累积式，s11 全保留。

## 3. 5 字段 cron 表达式

```text
minute hour day month weekday
   *     *    *    *      *    every minute
   0     9    *    *      *    every day at 09:00
  */5    *    *    *      *    every 5 minutes
   0     9    *    *     1-5   weekdays at 09:00
```

支持 `*`、`*/N`、`N`、`N-M`、`N,M,...`（README 第 52-62 行）。校验范围：minute 0-59 / hour 0-23 / day-of-month 1-31 / month 1-12 / day-of-week 0-6（`weekday` 0=Sun..6=Sat，匹配时 `cron_weekday = (moment.weekday()+1) % 7` 转换，[s12_cron_scheduler.py:1485](s12_cron_scheduler.py#L1485)）。

**验证**（函数级 9 例）：字段数错、minute/hour/day/month/weekday 各自越界、`*/0` step 非法、`5-1` range 反了——全部拒绝。

## 4. CronJob 数据结构（6+ 字段）

```python
@dataclass
class CronJob:                                  # [s12_cron_scheduler.py:1434]
    id: str                 # cron_ + 8 hex（uuid4().hex[:8]，排他重试）
    cron: str               # 5 字段表达式
    prompt: str             # 到点交给 agent 的任务
    recurring: bool         # True 重复 / False 一次性
    durable: bool           # True 持久化跨重启
    pending_delivery: bool = False   # 已入队待投递（防重复）
    last_fired: str | None = None    # "YYYY-MM-DD HH:MM"（同一分钟不再入队）
```

`pending_delivery` + `last_fired` 是防重复的两个闸（README 第 50 行、第 73 行）。

## 5. scheduler 线程 + queue processor 线程 + agent_lock

**两个 daemon 线程 + 一把互斥锁**（都只在 main 启动，import 不启线程——教材 README 第 124 行）：

- **scheduler 线程**（[s12_cron_scheduler.py:1725](s12_cron_scheduler.py#L1725)）：每 1s `poll_due_jobs(datetime.now())`，只管"到点入队"
- **queue processor 线程**（[s12_cron_scheduler.py:1729](s12_cron_scheduler.py#L1729)）：每 0.2s 检查队列 + `agent_lock.acquire(blocking=False)`，**不检查时间**——只管"有空就跑"
- **agent_lock**（[s12_cron_scheduler.py:1457](s12_cron_scheduler.py#L1457)）：main 的 user turn 用 `with SCHEDULER.agent_lock` 包住（[s12_cron_scheduler.py:2259](s12_cron_scheduler.py#L2259)），queue processor 抢不到锁就跳过——**scheduled turn 不能改变正在跑的 user session**（README 第 83-84 行）

两线程各管一件事，时间判断和投递判断解耦。

## 6. 7 步流程（schedule_cron → 校验 → 轮询 → 匹配 → enqueue → agent 空闲 → 注入）

```
① schedule_cron("0 9 * * *", "run tests")
② validate_cron（5 字段 + 范围）
③ scheduler 线程每 1s poll_due_jobs
④ cron_matches(expr, now) 匹配
⑤ _enqueue_due_job：pending_delivery=True + last_fired=分钟 → 入队（持久化失败回滚）
⑥ queue processor 线程：agent_lock 空闲时 run_agent_turn_locked()
⑦ agent_loop 轮首 consume_queue → messages.append("[Scheduled] run tests")
```

对应代码：schedule（[s12_cron_scheduler.py:1603](s12_cron_scheduler.py#L1603)）→ validate_cron（[1535](s12_cron_scheduler.py#L1535)）→ poll_due_jobs（[1660](s12_cron_scheduler.py#L1660)）→ cron_matches（[1480](s12_cron_scheduler.py#L1480)）→ _enqueue_due_job（[1645](s12_cron_scheduler.py#L1645)）→ queue_processor_loop（[1729](s12_cron_scheduler.py#L1729)）→ agent_loop 注入（[2146-2150](s12_cron_scheduler.py#L2146-L2150)）。

## 7. 持久化边界（durable vs 非 durable）

教材 README 第 107-116 行：

| 模式 | 存哪 | 重启后 |
|---|---|---|
| `durable=True` | `.scheduled_tasks.json` | load 回来 |
| `durable=False` | 内存 | 没了 |

- **原子写**：`save_durable_jobs` 写临时文件（`{name}.{pid}.{tid}.tmp`）再 `os.replace`（[s12_cron_scheduler.py:1551-1561](s12_cron_scheduler.py#L1551-L1561)）——不全写半截
- **损坏文件**：`load_durable_jobs` 报错并跳过，不崩（函数级验证 `{not json` 文件）
- **只存定义不存过期**：重启 load 任务定义，但**不重放进程关闭期间错过的时刻**（README 第 122 行）
- 投递是 at-least-once：模型接受 prompt 后、ack 落盘前进程退出，重启可能重复投递（README 第 116 行）

## 8. 失败回滚（持久化失败 + 模型调用失败）

**两处回滚，防止状态不一致**：

1. **持久化失败回滚**（`_enqueue_due_job`，[s12_cron_scheduler.py:1645-1658](s12_cron_scheduler.py#L1645-L1658)）：先置 `pending_delivery=True` + `last_fired`，`save_durable_jobs` 抛异常则恢复原状态、**不入队**——不能"内存已入队 + 磁盘没记录"；`schedule` 同理回滚内存（[s12_cron_scheduler.py:1618-1621](s12_cron_scheduler.py#L1618-L1621)）
2. **模型调用失败回滚**（agent_loop，[s12_cron_scheduler.py:2169-2172](s12_cron_scheduler.py#L2169-L2172)）：`del messages[scheduled_start:]` 移除注入的 `[Scheduled]` 消息 + `SCHEDULER.restore` 把任务退回队列（[s12_cron_scheduler.py:1708](s12_cron_scheduler.py#L1708)）——投递失败不丢任务

ack 也在 create 成功后立即做：recurring 清 `pending_delivery`、one-shot 从 `scheduled_jobs` 移除（[s12_cron_scheduler.py:1680-1706](s12_cron_scheduler.py#L1680-L1706)）。

## 9. OpenAI 协议差异

cron 本身是纯本地逻辑（无模型调用差异），协议差异回到 agent_loop 集成：

| 维度 | 本项目（OpenAI） | 教材（Anthropic） |
|---|---|---|
| `[Scheduled]` 注入 | append 独立 `role=user` 消息（[s12_cron_scheduler.py:2146-2148](s12_cron_scheduler.py#L2146-L2148)） | 同（code.py L632-634） |
| scheduled turn 的 active_request | `run_agent_turn_locked(None)` 传 `"(scheduled task)"`（[s12_cron_scheduler.py:2136](s12_cron_scheduler.py#L2136)） | 无此概念（Anthropic system 独立参数） |
| 压缩保留 system | `_with_system`（s09 已有） | 不需要（system 独立） |
| 工具 schema | `{"type":"function",...}` | `{"name","input_schema"}` |
| 工具结果 | `role=tool` 独立消息 | user content list 的 `tool_result` block |
| 判断停止 | `not msg.tool_calls` | `stop_reason != "tool_use"` |

`ask_user` 的非主线程拒绝（[s12_cron_scheduler.py:789](s12_cron_scheduler.py#L789)）是教材 `request_permission` 的协议无关适配：**scheduled turn 跑在 queue processor 线程，不能抢主终端的 input()**，直接拒绝（教材 README 第 123 行）。

## 11. N 个最佳实践亮点

1. **5 字段校验前置**（[s12_cron_scheduler.py:1535](s12_cron_scheduler.py#L1535)）：schedule 先 validate，非法表达式返错误串不给模型丢异常
2. **防重复双闸**：`pending_delivery`（已入队） + `last_fired`（同一分钟已触发）——函数级验证同分钟不重复、下一分钟再入队
3. **agent_lock 互斥**：scheduled turn 与 user turn 串行化，绝不抢 session
4. **`os.replace` 原子写**（[s12_cron_scheduler.py:1557](s12_cron_scheduler.py#L1557)）：temp + 替换，崩溃不留半截文件
5. **持久化失败回滚**（[s12_cron_scheduler.py:1645-1658](s12_cron_scheduler.py#L1645-L1658)）：磁盘没记录就不入队——状态一致
6. **模型失败回滚**（[s12_cron_scheduler.py:2169-2172](s12_cron_scheduler.py#L2169-L2172)）：`del` + `restore` 退回队列，任务不丢
7. **错过不补**：重启只 load 定义不重放过期时间——简单且明确
8. **损坏文件不崩**：`load_durable_jobs` 逐条校验（id 前缀/validate_cron/prompt 非空），坏记录跳过
9. **scheduled turn 不交互审批**（[s12_cron_scheduler.py:789](s12_cron_scheduler.py#L789)）：非主线程 `ask_user` 直接 deny——**重要安全设计**，用户点名的亮点
10. **线程只在 CLI 启动**：import 无副作用，测试/库使用安全
11. **one-shot/recurring 区分 ack**：一次性任务 ack 后移除、重复任务清 pending_delivery
12. **两线程职责解耦**：scheduler 只看时间、queue processor 只看队列和锁

## 12. ⚠️ 主观理解待补充 [❓ 用户补充]

代码能客观看出的摩擦点（作为线索）：

- **分钟级精度**：cron 最小单位是分钟，`last_fired` 用 `"YYYY-MM-DD HH:MM"` marker——秒级调度不支持
- **错过不补的取舍**：进程关闭期间到点的任务直接丢弃（重启不重放）——教材明确这是边界选择
- **scheduled turn 饿死可能**：用户一直输入时 `agent_lock` 一直被占，queue processor 抢不到锁，scheduled turn 排不上
- **ask_user 非主线程返回的拒绝消息**是 `"Permission denied by user"`，没说明"定时 turn 不能审批"——模型可能困惑
- **at-least-once 投递**：模型接受后 ack 前进程崩溃，重启会重复投递

但以下主观问题请补充：

- **错过不补**：如果任务很重要（比如"9 点跑测试"），进程关闭错过 9 点，重启后不补跑——你能接受吗？要不要设计"补跑"策略？[❓ 用户补充]
- **scheduled turn 的 `active_request`**：目前传 `"(scheduled task)"`，压缩时 `[Compacted]` 里的 Current user request 会显示这个占位——要不要改成实际 job.prompt？[❓ 用户补充]
- **e2e 里模型是否真的会主动用 schedule_cron**（还是用户明确指定才用）？[❓ 用户补充]
- **s13 agent teams 的触发**：cron 定时启动的 turn 如果跑在单 agent，s13 多 agent 时 scheduled turn 要不要分发给 team？[❓ 用户补充]
