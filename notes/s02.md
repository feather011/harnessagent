# s02 - Tool Use

## 1. 一句话核心

s01 的 `while True` 循环**一行没改**，只把"执行 bash 那一行"换成 `TOOL_HANDLERS` dispatch 查表：加一个工具 = TOOLS 数组加一条定义 + TOOL_HANDLERS 加一行映射。

教材原话：*"Add a tool, add just one handler"*；Harness Layer 定位为 **Tool Dispatch — Expanding the model's reach**（README 第 6-8 行）。动机是：s01 模型想"读文件"得拼 `cat path`，一层多余翻译浪费 token 且易错（README 第 16 行）；s02 给模型 5 个专用工具。

本项目实现见 [s02_tool_use.py:38-78](s02_tool_use.py#L38-L78)（工具定义）、[s02_tool_use.py:184-191](s02_tool_use.py#L184-L191)（dispatch 表）、[s02_tool_use.py:194-233](s02_tool_use.py#L194-L233)（loop）。

## 2. 从 1 工具到 5 工具：三块代码

### ① 工具 schema 定义（[s02_tool_use.py:38-78](s02_tool_use.py#L38-L78)）

5 个工具，每个是一个 OpenAI 协议 function schema：

| 工具 | 必填参数 | 可选参数 | 设计点 |
|---|---|---|---|
| bash | command | — | 同 s01，DENY 黑名单保留 |
| read_file | path | limit | limit 截行数，默认 None 不限制 |
| write_file | path, content | — | description 明说"会完全覆盖已有文件" |
| edit_file | path, old_text, new_text | — | `replace(..., 1)` 只换第一处，description 告知模型 |
| glob | pattern | — | `recursive=True` 支持 `**` 跨目录 |

### ② 工具实现函数（[s02_tool_use.py:85-166](s02_tool_use.py#L85-L166)）

- `run_bash`（85-106）：从 s01 原样带过来，未改
- `safe_path`（109-114）：新增，所有文件工具共用的工作区边界校验
- `run_read`（117-129）：limit 截行 + `...(N more lines)` 提示，超 50000 截断
- `run_write`（132-139）：自动建父目录，返回写入字节数
- `run_edit`（142-151）：old_text 不在则返回错误（不抛异常），替换第一处
- `run_glob`（154-166）：`root_dir=WORKDIR` + 逃逸过滤 + 排序输出

共同约定：**全部返回 str，错误也以字符串返回，不抛异常**（除 safe_path 抛 ValueError 由各函数捕获）。

### ③ dispatch 查表 + loop 里的一行改动（[s02_tool_use.py:184-233](s02_tool_use.py#L184-L233)）

```python
TOOL_HANDLERS = {"bash": run_bash, "read_file": run_read,
                 "write_file": run_write, "edit_file": run_edit, "glob": run_glob}
# loop 里：s01 是 run_bash(args["command"]), s02 是查表
handler = TOOL_HANDLERS.get(name)
output = handler(**args) if handler else f"Error: unknown tool '{name}'"
```

教材强调的核心（README 第 24 行）：s01 的 loop（LLM 调用、判断是否调工具、append 消息）**一行没改**，变动的只有 tool 执行那一行。

## 3. OpenAI 协议 vs Anthropic 协议差异（工具部分）

教材 s02 `code.py`（Anthropic）对项目 `s02_tool_use.py`（OpenAI/DeepSeek），聚焦工具定义与分发：

| 维度 | 本项目（OpenAI） | 教材（Anthropic） |
|---|---|---|
| 工具定义 | `{"type":"function","function":{"name","description","parameters"}}`（[L38-78](s02_tool_use.py#L38-L78)） | `{"name","description","input_schema"}` |
| 参数传递 | `call.function.arguments` 是 **JSON 字符串**，需 `json.loads`（[L210](s02_tool_use.py#L210)） | `block.input` 已是 **dict**，`**block.input` 直接用 |
| dispatch | `TOOL_HANDLERS.get(name)`，`name = call.function.name`（[L208](s02_tool_use.py#L208)） | `TOOL_HANDLERS[block.name]`，`block.name` |
| 结果回传 | `{"role":"tool","tool_call_id":call.id,"content":...}`（[L231-232](s02_tool_use.py#L231-L232)） | `{"type":"tool_result","tool_use_id":block.id}` |
| 多工具返回 | `msg.tool_calls` 列表 | `response.content` 里多个 `tool_use` block |

**最实际差异**：OpenAI 协议的工具参数是 JSON 字符串要自己解析（也就引入了坏 JSON 处理）；Anthropic 直接给 dict。

## 4. 本项目对教材 code.py 的主要适配

项目是基于 s01_agent_loop.py 扩展的，但相对于教材 s02 code.py 有以下可验证的差异：

1. **协议层**：工具 schema 用 `parameters`（带 `type`/`function` 包裹）而非 `input_schema`；结果用 `role=tool` 而非 `tool_result`（[L38-78](s02_tool_use.py#L38-L78)、[L231-232](s02_tool_use.py#L231-L232)）
2. **参数解析**：`call.function.arguments` 需 `json.loads`，并处理解析失败（[L209-219](s02_tool_use.py#L209-L219)）——教材无需此步
3. **WORKDIR**：`Path(__file__).resolve().parent` 而非教材的 `Path.cwd()`——脚本换目录跑，工作区仍锁定项目根（[L36](s02_tool_use.py#L36)）
4. **run_bash 环境**：优先 Git Bash `bash -c`，无 bash 才回退 `shell=True`；`timeout=30` 而非教材 120（[L85-106](s02_tool_use.py#L85-L106)）
5. **run_glob 增强**：`recursive=True`（支持 `**`）、`matches.sort()` 稳定输出（教材不递归、不排序）（[L154-166](s02_tool_use.py#L154-L166)）
6. **坏 JSON 信息链**：解析失败返回 `Error: invalid arguments JSON: <原因>` + `continue`，不让 handler 看到空 dict（[L211-219](s02_tool_use.py#L211-L219)）
7. **surrogate 清洗**：`_strip_surrogates()` 递归清洗模型回复里的孤立 surrogate，避免 openai SDK 3.0.0 序列化崩溃（[L169-181](s02_tool_use.py#L169-L181)）
8. **dispatch 容错**：`TOOL_HANDLERS.get(name)` + 未知工具错误消息 + `try/except` 单工具失败不影响后续（[L222-229](s02_tool_use.py#L222-L229)）

## 5. 7 个最佳实践亮点

1. **工作区边界校验**：`safe_path()` 用 `resolve()` 展开相对路径再 `is_relative_to(WORKDIR)`，逃逸抛 `ValueError`（[L109-114](s02_tool_use.py#L109-L114)）
2. **单工具失败隔离**：`try/except` 包 `handler(**args)`，一个工具出错只影响自己（[L226-229](s02_tool_use.py#L226-L229)）
3. **坏 JSON 直接反馈模型**：错误信息带 `tool_call_id` 且说明"invalid arguments JSON"，模型能关联并修正（[L211-219](s02_tool_use.py#L211-L219)）
4. **surrogate 防御**：清洗函数递归处理 dict/list/str，入 messages 和打印前都过（[L169-181](s02_tool_use.py#L169-L181)）
5. **错误以字符串返回**：所有工具函数 `try/except` 返回 `Error: ...`，模型能读错误自我修正，不抛异常（[L117-166](s02_tool_use.py#L117-L166)）
6. **description 写给模型看**：`write_file` 写明"会覆盖"、`edit_file` 写明"只替换第一处"——模型看不到函数体，只能靠 description 决定怎么调（[L38-77](s02_tool_use.py#L38-L77)）
7. **可观测性升级**：从 `$ <命令>` 变成 `> <工具名>(<参数>)`，人能看清 agent 调了哪个工具、参数是什么（[L221](s02_tool_use.py#L221)）
