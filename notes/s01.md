# s01 - Agent Loop

## 1. 一句话核心

一个 `while True` 循环：把用户问题交给模型，模型请求工具（`run_bash`）就执行并把结果回喂给模型，模型不再请求工具就退出并打印回答。

"模型负责决策，harness 负责执行。" 教材原话：*"One tool + one loop = one Agent"*，The Loop 是"模型与现实世界之间的第一座桥"（README 第 8 行）。没有这个循环，人就只能当中间层——手动执行命令、再把输出粘贴回聊天框（README "The Problem"）。

本项目实现见 [s01_agent_loop.py:79-106](s01_agent_loop.py#L79-L106)。

## 2. 5 步流程（带代码引用）

对应教材 README 的 5 步，映射到本项目行号：

| 步 | 动作 | 本项目代码 |
|---|---|---|
| ① | 用户问题进入 messages | [s01_agent_loop.py:120](s01_agent_loop.py#L120) `history.append({"role":"user","content":q})` |
| ② | 把 messages + tools 发给 LLM | [s01_agent_loop.py:81-83](s01_agent_loop.py#L81-L83) `client.chat.completions.create(model, messages, tools, max_tokens)` |
| ③ | 追加模型回复，判断是否调工具；没调 → 完成 | [s01_agent_loop.py:84-90](s01_agent_loop.py#L84-L90) `messages.append(msg)`；`if not msg.tool_calls: return` |
| ④ | 执行模型请求的工具并收集结果 | [s01_agent_loop.py:91-103](s01_agent_loop.py#L91-L103) 解析 `arguments` → `run_bash(command)` → 打印 |
| ⑤ | 把工具结果作为新消息回传，回到 ② | [s01_agent_loop.py:104-106](s01_agent_loop.py#L104-L106) `messages.append({"role":"tool", "tool_call_id", "content"})` |

教材的"两个信号"（README 第 30-33 行）：模型要工具 → 执行→回喂→继续；模型不要工具 → 退出。本项目用 `not msg.tool_calls` 表达"不要工具"。

## 3. OpenAI 协议 vs Anthropic 协议差异

教材 `code.py` 用 Anthropic 协议，本项目 `s01_agent_loop.py` 用 OpenAI 兼容协议（DeepSeek）。同一循环模式，协议表达不同：

| 维度 | 本项目（OpenAI 协议） | 教材（Anthropic 协议） |
|---|---|---|
| SDK | `openai` | `anthropic` |
| 客户端 | `OpenAI(api_key, base_url)`（[L25-28](s01_agent_loop.py#L25-L28)） | `Anthropic(base_url)` |
| SYSTEM 位置 | 放 messages[0] `{"role":"system"}`（[L110](s01_agent_loop.py#L110)） | `create` 的 `system=` 参数，不在 messages 里 |
| 创建请求 | `chat.completions.create(model, messages, tools)` | `messages.create(model, system, messages, tools)` |
| 工具定义 | `{"type":"function","function":{"name","description","parameters"}}`（[L33-48](s01_agent_loop.py#L33-L48)） | `{"name","description","input_schema"}` |
| 判断"调了工具" | `msg.tool_calls` 非空（[L86](s01_agent_loop.py#L86)） | `response.stop_reason == "tool_use"` |
| 工具参数 | `call.function.arguments`（JSON 字符串，需 `json.loads`，[L93](s01_agent_loop.py#L93)） | `block.input`（已是 dict） |
| 工具调用 ID | `call.id`（[L98](s01_agent_loop.py#L98)） | `block.id` |
| 回传工具结果 | 独立角色 `{"role":"tool","tool_call_id",...}`（[L104-106](s01_agent_loop.py#L104-L106)） | 包进 `{"role":"user","content":[{"type":"tool_result","tool_use_id",...}]}` |
| assistant 回复回传 | 直接 append 消息对象 `messages.append(msg)`（[L85](s01_agent_loop.py#L85)） | `messages.append({"role":"assistant","content":response.content})` |

**关键差异**：Anthropic 的 tool_result 用 `role="user"` 包裹，OpenAI 用独立 `role="tool"` + `tool_call_id` 关联；Anthropic 有显式 `stop_reason`，OpenAI 靠 `msg.tool_calls` 是否为空判断。

## 4. 本项目对参考代码的 7 项适配

参考代码是用户最初贴的 openai 1.x/2.x 版（含 `max_temperature=None`）。项目脚本 docstring（[L4-8](s01_agent_loop.py#L4-L8)）声明了适配，展开为 7 项：

1. **协议参数适配**：`max_temperature` 在 openai 3.0.0 已移除，改用 `max_tokens`；`temperature` 不传，走 DeepSeek 默认（[L81-82](s01_agent_loop.py#L81-L82)）
2. **客户端指向 DeepSeek**：`OpenAI(api_key, base_url)` 从 `DEEPSEEK_*` 环境变量读取（[L24-29](s01_agent_loop.py#L24-L29)）
3. **Git Bash 优先**：`shutil.which("bash")` 存在则 `bash -c`，避免 cmd.exe 没有 `ls/cat` 等 unix 命令；找不到才回退 `shell=True`（[L52](s01_agent_loop.py#L52)、[L59-68](s01_agent_loop.py#L59-L68)）
4. **控制台 UTF-8**：`sys.stdout/stderr.reconfigure(encoding="utf-8")`，避免 Windows 终端（GBK）中文乱码（[L20-22](s01_agent_loop.py#L20-L22)）
5. **SYSTEM 补进对话**：参考代码定义了 `SYSTEM` 却未使用；本项目作为 `messages[0]` 生效（[L31](s01_agent_loop.py#L31)、[L110](s01_agent_loop.py#L110)）
6. **健壮性兜底**：`TimeoutExpired` 捕获返回错误信息（参考代码会直接抛崩）；`json.loads/KeyError` 失败回传 `Error: bad function arguments`；`timeout=30`（[L69-70](s01_agent_loop.py#L69-L70)、[L92-100](s01_agent_loop.py#L92-L100)、[L62](s01_agent_loop.py#L62)）
7. **可观测性补全**：最终回答在 `agent_loop` 内打印（参考代码该处是占位 `pass`）；所有 `print` 加 `flush=True` 实时输出（[L88-89](s01_agent_loop.py#L88-L89)、[L101-103](s01_agent_loop.py#L101-L103)）

## 5. 7 个最佳实践亮点

从代码里直接可见的安全/健壮性/可观测性设计：

1. **危险命令黑名单**：`DENY` 列表（`rm -rf /`、`sudo`、`shutdown`、`reboot`、`> /dev/`）先拦截再执行（[L50](s01_agent_loop.py#L50)、[L56-57](s01_agent_loop.py#L56-L57)）
2. **命令超时保护**：`subprocess.run(..., timeout=30)`，超时 kill 并返回错误，防止一条命令挂死整个 agent（[L62](s01_agent_loop.py#L62)、[L69-70](s01_agent_loop.py#L69-L70)）
3. **输出截断**：>50000 字符截断并标注 `(output truncated)`，防止巨型输出撑爆模型上下文窗口（[L74-75](s01_agent_loop.py#L74-L75)）
4. **容错解码**：`errors="replace"`，GBK/UTF-8 混合输出不抛 UnicodeDecodeError（[L62](s01_agent_loop.py#L62)、[L67](s01_agent_loop.py#L67)）
5. **执行可观测性**：`$ <命令>` 实时打印 + 输出前 200 字符预览，人能看到 agent 在干什么（[L101-103](s01_agent_loop.py#L101-L103)）
6. **坏参数防御**：模型返回的 JSON 参数解析失败时不崩溃，回传错误让模型自己修正（[L92-100](s01_agent_loop.py#L92-L100)）
7. **密钥与退出**：密钥从 `.env` 经 `load_dotenv()` 加载不硬编码；`EOFError/KeyboardInterrupt` 优雅退出（[L24-29](s01_agent_loop.py#L24-L29)、[L113-117](s01_agent_loop.py#L113-L117)）
