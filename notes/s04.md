# s04 - Hooks

## 1. 一句话核心

把扩展逻辑从 loop 里挪到"挂在 loop 上的 hook"上：loop 只调用 `trigger_hooks()`，具体做什么由注册表决定。

教材原话：*"Hang on the loop, don't write into it"*；Harness Layer 定位为 **Hooks — Extension points that don't invade the loop**（README 第 7-9 行）。动机：s03 每加一个功能（打日志、自动 git add、通知）都要改 `agent_loop`，循环很快就面目全非（README 第 15-34 行）。loop 应该是稳定内核，扩展挂在外面。

本项目实现见 [s04_hooks.py:259-275](s04_hooks.py#L259-L275)（注册表 + 触发）、[s04_hooks.py:324-328](s04_hooks.py#L324-L328)（注册）、[s04_hooks.py:331-384](s04_hooks.py#L331-L384)（loop 只调 trigger）。

## 2. 4 类事件 + 5 个 hook（带代码引用）

| 事件 | 触发时机 | 本项目 hook | 返回非 None 的效果 |
|---|---|---|---|
| UserPromptSubmit | 用户输入后、进 LLM 前 | context_inject_hook（[L279-282](s04_hooks.py#L279-L282)） | 无（只记录） |
| PreToolUse | 工具执行前 | log_hook + permission_hook（[L285-305](s04_hooks.py#L285-L305)） | **拦截该工具调用** |
| PostToolUse | 工具执行后 | large_output_hook（[L308-313](s04_hooks.py#L308-L313)） | 无（只警告） |
| Stop | loop 即将退出 | summary_hook（[L316-320](s04_hooks.py#L316-L320)） | **强制继续**（注入消息再跑一轮） |

**注册表**（[L260-275](s04_hooks.py#L260-L275)）——`HOOKS = {}` + `setdefault` 动态建列表，加新事件不用改定义：
```python
def register_hook(event: str, callback):
    HOOKS.setdefault(event, []).append(callback)

def trigger_hooks(event: str, *args):
    for callback in HOOKS.get(event, []):   # .get 防未注册事件 KeyError
        result = callback(*args)            # *args 全量解包
        if result is not None:              # is not None：空串/0/False 也算拦截
            return result
    return None
```

**5 个 hook**（[L279-320](s04_hooks.py#L279-L320)）：
1. `context_inject_hook(query)`：记录用户输入，截断 50 字符，`return None` 放行
2. `log_hook(name, args)`：记录工具调用，灰色 ANSI，`return None`
3. `permission_hook(name, args)`：**s03 的 check_permission 原样搬过来**——Gate1 硬拒 / Gate2 问用户 / `_DENY_ALL`，返回拒绝消息字符串
4. `large_output_hook(name, args, output)`：输出 >100000 警告，`return None`
5. `summary_hook(messages)`：退出前打印 `role="tool"` 消息计数，`return None` 放行退出

**注册**（[L324-328](s04_hooks.py#L324-L328)）——模块底部、`__main__` 之外，确保 import 时即注册：
```python
register_hook("UserPromptSubmit", context_inject_hook)
register_hook("PreToolUse", log_hook)         # log 先注册 → 先跑
register_hook("PreToolUse", permission_hook)  # permission 后注册 → 后跑
register_hook("PostToolUse", large_output_hook)
register_hook("Stop", summary_hook)
```

**loop 里的 3 处 trigger**（[L340](s04_hooks.py#L340)、[L361](s04_hooks.py#L361)、[L380](s04_hooks.py#L380)）：Stop 在退出前、PreToolUse 在 handler 前（拦截则回传 `blocked` 并 `continue`）、PostToolUse 在 handler 后（被 PreToolUse 拦的**不触发** PostToolUse，因为没产生 output）。

## 3. OpenAI 协议 vs Anthropic 协议差异（hooks 部分）

教材 s04 `code.py`（Anthropic）对项目 `s04_hooks.py`（OpenAI/DeepSeek）：

| 维度 | 本项目（OpenAI） | 教材（Anthropic） |
|---|---|---|
| hook 签名 | `(name, args)` / `(name, args, output)`（[L285](s04_hooks.py#L285)、[L308](s04_hooks.py#L308)） | `(block)` / `(block, output)`，内部取 `block.name/input` |
| 参数来源 | `call.function.arguments` → `json.loads` 的 dict | `block.input` 已是 dict |
| Stop 统计方式 | 数 `role == "tool"` 消息（[L318](s04_hooks.py#L318)） | 遍历 `tool_result` block |
| 注册表结构 | `HOOKS = {}` + `setdefault`（[L260-265](s04_hooks.py#L260-L265)） | `HOOKS = {4个key: []}` 写死 |
| trigger 防御 | `HOOKS.get(event, [])`（[L271](s04_hooks.py#L271)） | `HOOKS[event]` 直接索引 |

**关键差异**：OpenAI 协议没有 `block` 对象，hook 统一收 `(name, args)`；`setdefault` + `.get` 让注册表对新事件天然开放（教程写死 4 个 key）。

## 4. 本项目对参考代码（教材 code.py）的适配

1. **注册表动态化**：`HOOKS = {}` + `setdefault`，而非教材写死 4 个 key——加新事件（如 OnError）不用改定义（[L260-265](s04_hooks.py#L260-L265)）
2. **trigger 防 KeyError**：`HOOKS.get(event, [])`，未注册事件返回 None 而非崩溃（[L271](s04_hooks.py#L271)）
3. **register 顺序调整**：log_hook 先、permission_hook 后（教材相反）——每次工具调用先 log 再 permission，log 永远可见（[L324-326](s04_hooks.py#L324-L326)）
4. **签名适配**：`(block)` → `(name, args)`，不依赖 SDK 对象；summary 数 `role="tool"`（OpenAI 协议）（[L285](s04_hooks.py#L285)、[L318](s04_hooks.py#L318)）
5. **stdin reconfigure(utf-8)**：修复 s04 暴露的 surrogate 边界——s02 的清洗只盖了 messages 流向 LLM 的路，hook 直接 print 用户输入绕过了这条边界，必须从 stdin 根上解（[L27-28](s04_hooks.py#L27-L28)）
6. **hook 打印统一清洗**：`context_inject_hook` 和 `log_hook` 都过 `_strip_surrogates`，对称防御（[L281](s04_hooks.py#L281)、[L288](s04_hooks.py#L288)）
7. **permission 逻辑零改动搬移**：s03 的 8 个 DENY_LIST、4 条规则、`ask_user` 改进版、`_DENY_ALL` 全部保留，只是从 `check_permission` 挪进 `permission_hook`（[L292-305](s04_hooks.py#L292-L305)）

## 5. 7 个最佳实践亮点

1. **注册表动态开放**：`setdefault` 建列表，新事件零改动接入（[L265](s04_hooks.py#L265)）
2. **`.get` 防御**：未注册事件不抛 KeyError（[L271](s04_hooks.py#L271)）
3. **注册放模块加载时**：不在 `__main__` 里注册，import 即生效，测试不踩空（[L323](s04_hooks.py#L323)）
4. **`is not None` 拦截语义**：空串/0/False 也当拦截结果，只有 None 放行——避免空串被误判"没拦"（[L273](s04_hooks.py#L273)）
5. **Stop hook 可强制继续**：返回非 None → 注入消息再跑一轮，为后续 goal loop 预留机制（[L340-343](s04_hooks.py#L340-L343)）
6. **被拦的工具不触发 PostToolUse**：没有 output 就没东西可 post，语义正确（[L361-380](s04_hooks.py#L361-L380)）
7. **hook 打印统一清洗**：所有打印用户/工具内容的 hook 过 `_strip_surrogates`，防御纵深一致（[L281](s04_hooks.py#L281)、[L288](s04_hooks.py#L288)）
