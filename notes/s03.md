# s03 - Permission

## 1. 一句话核心

在工具执行前插入一道权限闸门：**先硬拒、再问人、都不命中才放行**。s02 的 loop 一行没改，只加了一句 `check_permission()`。

教材原话：*"Check permissions before executing"*，Harness Layer 定位为 **Permission — a gate before tool execution**（README 第 7-8 行）。动机：s02 的文件工具被 `safe_path` 保护，但 bash 无限制——"clean up the project" 就可能真跑 `rm -rf /`，安全不能靠信任模型，要靠代码检查（README 第 14-16 行）。

本项目实现见 [s03_permission.py:38-122](s03_permission.py#L38-L122)（闸门），接入点 [s03_permission.py:302-311](s03_permission.py#L302-L311)。

## 2. 三道闸门（带代码引用）

| Gate | 作用 | 命中时 |
|---|---|---|
| 1. Deny List | 永久禁止的操作（`rm -rf /`、`sudo`…） | 立即拒绝，不问用户 |
| 2. Rule Matching | 需上下文判断的操作（越界读写、`rm` 文件…） | 交给 Gate 3 |
| 3. User Approval | 暂停等用户确认 | 用户决定 allow / deny |

都不命中 → 直接执行（大多数常规操作走这条路）。教材原话强调：*"it is not a complete security boundary"*（README 第 42 行）——关键词匹配不是完整安全边界。

**Gate 1** 硬拒列表（[s03_permission.py:40](s03_permission.py#L40)、[75-82](s03_permission.py#L75-L82)）：
```python
DENY_LIST = ["rm -rf /", "sudo", "shutdown", "reboot", "mkfs", "dd if=", "> /dev/sda", "> /dev/"]
# check_deny_list: 先折叠连续空白防 "rm -rf  /" 双空格绕过，再全词 + 子串匹配
```

**Gate 2** 规则（[s03_permission.py:43-69](s03_permission.py#L43-L69)）——每条规则 = `tools` 列表 + `check` lambda + `message`：
- 文件工具越出工作区（教程基线 1）
- bash 疑似破坏性命令 `rm / unlink / del / rmdir / > /etc/ / chmod 777`（教程基线 2，含删除类扩展）
- 写敏感文件 `.env` / `*.pem` / `*.key` / `.gitignore`（扩展 B）
- 装包 `pip install` / `npm install`（扩展 C）

**Gate 3** 问用户（[s03_permission.py:93-107](s03_permission.py#L93-L107)）——改进版：回车=拒绝、`q`=本会话全拒（置 `_DENY_ALL`）、无效输入循环。

**串起来**（[s03_permission.py:110-122](s03_permission.py#L110-L122)）：
```python
def check_permission(tool_name, args) -> tuple:   # (是否允许, 拒绝原因)
    if _DENY_ALL:
        return False, "Denied by user (deny all)"
    if tool_name == "bash":
        reason = check_deny_list(args.get("command", ""))
        if reason:
            return False, f"dangerous command: {reason}"   # Gate 1 硬拒，不问
    reason = check_rules(tool_name, args)
    if reason:
        if ask_user(tool_name, args, reason) == "deny":
            return False, reason
    return True, ""
```

**接入 loop**（[s03_permission.py:302-311](s03_permission.py#L302-L311)）：`allowed, reason = check_permission(name, args)`；拒绝则回传 `Permission denied: <reason>` 给模型并 `continue`。

## 3. OpenAI 协议 vs Anthropic 协议差异（权限部分）

教材 s03 `code.py`（Anthropic）对项目 `s03_permission.py`（OpenAI/DeepSeek）：

| 维度 | 本项目（OpenAI） | 教材（Anthropic） |
|---|---|---|
| check_permission 签名 | `(tool_name: str, args: dict)`（[L110](s03_permission.py#L110)） | `(block)`，内部取 `block.name` / `block.input` |
| 参数来源 | `call.function.arguments` → `json.loads` 后的 dict | `block.input` 已是 dict |
| 返回值 | `(bool, reason)` 元组，拒绝原因可回传 | `bool`，拒绝消息写死 `"Permission denied."` |
| 拒绝回传 | `Permission denied: <reason>`（[L305](s03_permission.py#L305)） | `Permission denied.`（模糊） |

**关键差异**：教材的 `check_permission(block)` 绑死 SDK 对象；项目拆成 `(tool_name, args)` 更通用，且返回 `(bool, reason)` 让"拒绝消息带原因"成为可能——模型能看到被拒的理由，下轮不再重复同一操作。

## 4. 本项目对参考代码（教材 code.py）的适配

1. **签名通用化**：`check_permission(block)` → `(tool_name, args)`，不依赖 SDK 对象（[L110](s03_permission.py#L110)）
2. **返回 (bool, reason)**：拒绝原因带回 loop，`denied_msg` 带 reason（教材只返回 bool，消息写死）（[L110-122](s03_permission.py#L110-L122)、[L305](s03_permission.py#L305)）
3. **ask_user 改进版**：`q`=deny all（`_DENY_ALL` 全局）、回车=拒绝、无效输入循环重问（教材一次输入定生死）（[L93-107](s03_permission.py#L93-L107)）
4. **DENY_LIST 8 个**：教程 7 个 + `> /dev/` 兜底（拦任意设备重定向，不只 `/dev/sda`）（[L40](s03_permission.py#L40)）
5. **防绕过**：`check_deny_list` 折叠连续空白（防 `rm -rf  /`）+ 全词/子串混合；Gate2 补 `unlink/del/rmdir` 删除类（[L75-82](s03_permission.py#L75-L82)、[L50-56](s03_permission.py#L50-L56)）
6. **PERMISSION_RULES 4 条**：教程基线 2 + 扩展 B（敏感文件）+ C（装包）（[L43-69](s03_permission.py#L43-L69)）
7. **双层防御**：`check_permission` 之外，`run_bash` 内置 `DENY` 兜底（s02 保留）（[L168-169](s03_permission.py#L168-L169)、[L174-176](s03_permission.py#L174-L176)）

## 5. 7 个最佳实践亮点

1. **三闸门固定顺序**：硬拒先于软问——`rm -rf /` 直接拒，绝不让用户背锅（[L114-117](s03_permission.py#L114-L117)）
2. **拒绝带 reason 回传**：`Permission denied: dangerous command: sudo`，模型能关联原因、下轮改策略（[L303-311](s03_permission.py#L303-L311)）
3. **防双空格绕过**：`" ".join(command.split())` 折叠空白再匹配，`rm -rf  /` 也拦（[L78](s03_permission.py#L78)）
4. **q = deny all 全局开关**：用户一次拒绝全部，不用每条命令都问（[L102-104](s03_permission.py#L102-L104)、[L112-113](s03_permission.py#L112-L113)）
5. **保守默认**：`ask_user` 回车（空输入）= 拒绝，无效输入循环重问（[L99-107](s03_permission.py#L99-L107)）
6. **双层防御**：闸门在前 + `run_bash` 内置 DENY 兜底，纵深防御（[L174-176](s03_permission.py#L174-L176)）
7. **规则数据化**：`PERMISSION_RULES` 是「工具 + lambda + 消息」的列表，加规则只 append 一条，不动 loop（[L43-69](s03_permission.py#L43-L69)）

- Gate2 的 `rm ` 子串能被 `unlink`/`del`/`rmdir`/`python os.remove` 绕过——`unlink/del/rmdir` 已补，`python os.remove` 这类**关键词方案覆盖不了**，是 s03 的架构边界（教材 README 也明说 "not a complete security boundary"）
