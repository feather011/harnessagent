# s05 - TodoWrite 我的理解

## 1. 一句话核心

给 agent 加一个"计划工具" `todo_write`：维护内存里的任务清单（pending → in_progress → completed），连续 3 轮工具调用不更新清单就注入 `<reminder>` 提醒它回到计划。

教材原话：*"An agent without a plan goes wherever the wind blows"*；Harness Layer 定位为 **Planning — Let the Agent think before it acts**（README 第 7-9 行）。动机是：复杂任务里模型被不断灌入的工具结果淹没，会忘记原始目标——10 步重构做到第 3 步就开始即兴发挥（README 第 15-19 行）。

**关键认知**（README 第 110 行）：*"todo_write doesn't give the Agent any additional execution capability. What it adds is planning capability."*——它不增加执行能力，只增加规划能力。

本项目实现见 [s05_todo_write.py:103-162](s05_todo_write.py#L103-L162)（TodoManager + dispatch）、[s05_todo_write.py:206-219](s05_todo_write.py#L206-L219)（工具 schema）、[s05_todo_write.py:452-456](s05_todo_write.py#L452-L456)（reminder）。

## 2. TodoManager 三大职责 + 5 条验证规则

### ① state holder（[s05_todo_write.py:108-109](s05_todo_write.py#L108-L109)）
```python
def __init__(self):
    self.items: list[dict] = []   # module-level 单例的状态
```
`TODO = TodoManager()` 是 module-level（[L154](s05_todo_write.py#L154)），**跨多 query 共享**——第二次 query 看到的 todo 是上次的延续。

### ② validator（[s05_todo_write.py:111-143](s05_todo_write.py#L111-L143)，update 方法）
`update(todos)`：解析 str → list（JSON 失败 `ast.literal_eval` 兜底）→ 逐条验证 → 替换 `self.items` → 返回 `render()`。违反约束 `raise ValueError`。

### ③ renderer（[s05_todo_write.py:145-151](s05_todo_write.py#L145-L151)）
```python
[>] 重构 utils.py
[ ] 跑测试
[x] 读 README

(1/3 completed)
```
`render()` 的输出**同时**回给模型（return）——模型靠它看到当前清单状态。

### 5 条验证规则（[s05_todo_write.py:120-140](s05_todo_write.py#L120-L140)）

| 规则 | 位置 | 说明 |
|---|---|---|
| 是 list | [L120](s05_todo_write.py#L120) | `isinstance(todos, list)` |
| ≤ 20 个 | [L122](s05_todo_write.py#L122) | 与 schema 的 `maxItems: 20` 对齐 |
| content 非空 | [L129-131](s05_todo_write.py#L129-L131) | 先 `.strip()` 再判空，"  " 也算空 |
| status 合法 | [L132-134](s05_todo_write.py#L132-L134) | 只允许 `pending/in_progress/completed`，与 schema `enum` 对齐 |
| 唯一 in_progress | [L138-140](s05_todo_write.py#L138-L140) | 强约束：同一时刻只允许一个进行中 |

额外一条：**each todo is object**（[L127-128](s05_todo_write.py#L127-L128)），防御模型传非 dict 项。

## 3. rounds_since_todo 计数器的工作流

**函数内部初始化**（[s05_todo_write.py:396](s05_todo_write.py#L396)），不是 module-level——每轮 `agent_loop` 独立计数，跨 query 重置：

```python
def agent_loop(messages):
    rounds_since_todo = 0                # ① 函数内初始化
    while True:
        ...
        used_todo = False                # ② 本轮是否有 todo_write 调用
        for call in msg.tool_calls:
            if call.function.name == "todo_write":
                used_todo = True         #    累积：任何一处调用都算（不能只查最后一个）
        ...
        rounds_since_todo = 0 if used_todo else rounds_since_todo + 1   # ③ 更新
        if rounds_since_todo >= 3:                                       # ④ 达 3
            messages.append({"role": "user",
                             "content": "<reminder>Update your todos.</reminder>"})
            rounds_since_todo = 0        # ⑤ 注入后归零，不连续打扰
```

三个关键点（[L452-456](s05_todo_write.py#L452-L456)）：
1. `rounds_since_todo` 在函数内初始化 → 不跨 query 累计（否则单 query 任务也会被提醒）
2. `used_todo` 用**累积**判断（[L415-416](s05_todo_write.py#L415-L416)）→ 本轮有任何 todo_write 就 reset
3. 注入后归零 → 不 3+3+3 连续刷屏

**典型流程**（README 第 108 行）：先 todo_write 列全部步骤（全 pending）→ 挑一个置 in_progress → 做完置 completed → 看下一个 pending → 继续。

## 4. OpenAI 协议 vs Anthropic 协议差异

教材 s05 `code.py`（Anthropic）对项目 `s05_todo_write.py`（OpenAI/DeepSeek），重点在工具注册 + reminder 注入：

| 维度 | 本项目（OpenAI） | 教材（Anthropic） |
|---|---|---|
| todo_write schema | `parameters` + `type`/`function` 包裹，`maxItems/minLength/enum`（[L206-219](s05_todo_write.py#L206-L219)） | `input_schema`，同样约束 |
| dispatch 注册 | `TOOL_HANDLERS["todo_write"] = run_todo_write`（[L329](s05_todo_write.py#L329)） | 相同（[code.py L198](D:\learn-claude-code\learn-claude-code\s05_todo_write\code.py)） |
| used_todo 检测 | `for call in msg.tool_calls: if call.function.name == "todo_write"`（[L415-416](s05_todo_write.py#L415-L416)） | `for block in response.content: if block.name == "todo_write"` |
| **reminder 注入方式** | 独立 `role="user"` 消息 + `<reminder>` 标签（[L455](s05_todo_write.py#L455)） | `results.append({"type":"text","text":"<reminder>..."})`，作为 tool_result 集合里的一个 text block |

**关键差异（reminder 注入）**：Anthropic 有 `results` 列表（tool_result + text block 混在一起回传），reminder 是其中一个 text block，随 tool 结果一起走 `role="user"` 包裹。**OpenAI 协议没有 results 集合**，每条 tool 消息独立 append——所以 reminder 注入成独立 `role="user"` 消息 + `<reminder>` 标签，靠标签让模型识别为 harness 内部信号而非用户新问题。

## 6. N 个最佳实践亮点

1. **`_MARKERS` 类常量**（[L106](s05_todo_write.py#L106)）：状态→标记的映射集中定义，render 只查表，改格式只动一处
2. **`content.strip()` 判空**（[L129](s05_todo_write.py#L129)）：纯空白也算空，防止模型传 `"  "` 占位
3. **each todo is object 防御**（[L127-128](s05_todo_write.py#L127-L128)）：防模型传字符串项（`"abc"`）导致 `.get()` 崩
4. **`ast.literal_eval` 而非 `eval`**（[L118](s05_todo_write.py#L118)）：解析 str 兜底但不执行任意代码，防注入
5. **唯一 in_progress 强约束**（[L138-140](s05_todo_write.py#L138-L140)）：设计哲学——模型同一时刻只聚焦一件事
6. **验证失败转错误字符串**（[L157-162](s05_todo_write.py#L157-L162)）：`run_todo_write` 捕获 ValueError 返回 `Error: <原因>`，模型能读错误自我修正，不抛给 loop
7. **schema 与 validator 双对齐**：`maxItems: 20` / `minLength: 1` / `enum` 与 update 校验规则一致——模型在工具描述里就看到限制（[L210-214](s05_todo_write.py#L210-L214) vs [L120-140](s05_todo_write.py#L120-L140)）

## 7. ⚠️ 主观理解待补充 [❓ 用户补充]

代码能客观看出的摩擦点（作为线索）：

- `rounds_since_todo` 只在**单次 query 内**计数（函数内初始化），真实 API 下模型要么快速完成任务、要么调 todo_write，"连续 3 轮不更新"很难自然凑出，reminder 端到端难测（函数级 mock 已验证 3 轮/3+3/重置）
- OpenAI 协议下 reminder 注入成了独立 `role="user"` 消息（Anthropic 是 results 里的 text block）——这两种形式对模型行为的影响差异未验证
